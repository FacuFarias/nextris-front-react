# Veterinary mode UI

The application reads `patient_mode` from the existing public `/api/app-config` endpoint. There is
no client-authoritative mode switch. Human mode retains the original components; veterinary mode
specializes the same patient, admission, appointment, upload and template routes using the existing
layout, controls, TanStack Query, Axios and Zod. The server enforces mode, validation and permissions.

## Staff flow

- Patients becomes Animals. Register an animal by name; species/raze and birth date may be unknown
  during provisional registration. No owner DNI or patient surname is required.
- Select an animal to edit demographics, append weight/clinical history, link responsible parties,
  create orders/appointments, or upload DICOM for an explicitly selected order.
- Ownership history is preserved. Ending a relationship revokes that animal's portal authorization.
  Portal access must be explicitly authorized; it is not implied by an owner relationship.
- Responsible parties, portal accounts/recovery, species/raze catalogs, institution-defined protocols,
  and simple report templates are managed in the corresponding tabs, subject to saved permissions.
- Reporting retains the normal editor and workflow, with veterinary context and the existing PDF.
- DICOM identity reconciliation requires explicit confirmation. The original upload is preserved;
  failures to transfer to PACS are reported rather than presented as successful uploads.

## Responsible flow

Login uses the existing `/pacientes` entry, relabeled Portal de responsables. The account must change
its random initial password. `/inicio` and `/estudios` display Mis animales, with selection, visible
studies, finalized report/PDF and study-scoped images. `/mis-datos` edits only the responsible's own
contacts. The owner does not receive staff permissions or a general PACS access token.

The API checks current responsibility on every clinical read. A completed transfer gives the new
authorized responsible access to the animal's entire publicable history; the previous responsible
loses access even if its browser session remains open. Existing report publication rules still apply.

Nexi, structured reports and MWL remain disabled. No equipment or clinical dosing instructions are
precached or generated by this UI.

## Checks

```bash
npm ci
npm run typecheck
npm run build
npx eslint src/modules/veterinary
npx playwright install chromium
VETERINARY_BROWSER_URL=http://127.0.0.1:8083 VETERINARY_BROWSER_FIXTURES=/tmp/veterinary-fixtures.json npm run test:veterinary:browser
```

Generate the fixture file with the backend's disposable-database helper. Serve this frontend build
on localhost with `/api` proxied to that test backend. The browser suite refuses public targets.
Optional `PLAYWRIGHT_EXECUTABLE_PATH` selects an existing Chromium; `PLAYWRIGHT_MODULE_PATH`
is available for preinstalled tooling. The original repository's ESLint baseline contains unrelated
errors; new veterinary modules are checked independently and the full baseline should be reported.

Production serves `dist/` with Nginx. Rebuild and deploy the backend/frontend pair; changing the
Vite development server does not update the published site. Do not commit private `.env` files,
browser fixtures, uploads, build output, database backups or portal credentials.

## Patient directory layout

`/buscar-pacientes` uses the Worklist page container, shared `TablaDynamic`, purple table header,
filter panel, column search/sorting/visibility and pagination. Its primary tabs are Animales and
Responsables. Protocols, simple templates and catalogs remain available from Configuración.
Animal/owner creation and detail editing use the existing Modal component. The layout fills the
available desktop width and supports mobile views without a document-wide horizontal scrollbar.

Animal filters: name/PatientID/owner search, species, breed and presence of an active responsible
relationship. Responsible filters: name/document/email/phone search, person/organization and
active/inactive status. Column filters, sorting and pagination run on the server over the complete
matching set. Directory controls and detail actions retain the existing saved permissions.

## MCP disabled

CDIVET builds with `VITE_MCP_BRIDGE_ENABLED=false`. The MCP widget, bridge event listeners
and polling remain unmounted. The development proxy also requires explicit opt-in with `true`.
Production Nginx rejects `/assistant-bridge` and its subpaths.
